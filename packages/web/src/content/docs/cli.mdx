The anymous CLI by default starts the [TUI](/docs/tui) when run without any arguments.

```bash
anymous
```

But it also accepts commands as documented on this page. This allows you to interact with anymous programmatically.

```bash
anymous run "Explain how closures work in JavaScript"
```

---

### tui

Start the anymous terminal user interface.

```bash
anymous [project]
```

#### Flags

| Flag                                        | Short | Description                                                             |
| ------------------------------------------- | ----- | ----------------------------------------------------------------------- |
| <nobr><code>{"--continue"}</code></nobr>    | `-c`  | Continue the last session                                               |
| <nobr><code>{"--session"}</code></nobr>     | `-s`  | Session ID to continue                                                  |
| <nobr><code>{"--fork"}</code></nobr>        |       | Fork the session when continuing (use with `--continue` or `--session`) |
| <nobr><code>{"--prompt"}</code></nobr>      |       | Prompt to use                                                           |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | Model to use in the form of provider/model                              |
| <nobr><code>{"--agent"}</code></nobr>       |       | Agent to use                                                            |
| <nobr><code>{"--auto"}</code></nobr>        |       | Auto-approve permissions that are not explicitly denied                 |
| <nobr><code>{"--port"}</code></nobr>        |       | Port to listen on                                                       |
| <nobr><code>{"--hostname"}</code></nobr>    |       | Hostname to listen on                                                   |
| <nobr><code>{"--mdns"}</code></nobr>        |       | Enable mDNS discovery                                                   |
| <nobr><code>{"--mdns-domain"}</code></nobr> |       | Custom mDNS domain name                                                 |
| <nobr><code>{"--cors"}</code></nobr>        |       | Additional browser origin(s) to allow CORS                              |

## Commands

The anymous CLI also has the following commands.

---

### agent

Manage agents for anymous.

```bash
anymous agent [command]
```

---

#### create

Create a new agent with custom configuration.

```bash
anymous agent create
```

This command will guide you through creating a new agent with a custom system prompt and permission configuration. Anything you don't allow is denied in the generated agent's frontmatter.

#### Flags

| Flag                                        | Short | Description                                                                                                                                                                                                                |
| ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr><code>{"--path"}</code></nobr>        |       | Directory to write the agent file to (defaults to global or `.anymous/agent` based on the prompt)                                                                                                                         |
| <nobr><code>{"--description"}</code></nobr> |       | What the agent should do                                                                                                                                                                                                   |
| <nobr><code>{"--mode"}</code></nobr>        |       | Agent mode: `all`, `primary`, or `subagent`                                                                                                                                                                                |
| <nobr><code>{"--permissions"}</code></nobr> |       | Comma-separated list of permissions to allow (default: all). Available: `bash`, `read`, `edit`, `glob`, `grep`, `webfetch`, `task`, `todowrite`, `websearch`, `lsp`, `skill`. Anything omitted is denied. Alias: `--tools` |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | Model to use, in `provider/model` format                                                                                                                                                                                   |

Passing all of `--path`, `--description`, `--mode`, and `--permissions` runs the command non-interactively.

---

#### list

List all available agents.

```bash
anymous agent list
```

### attach

Attach a terminal to an already running anymous backend server started via `serve` or `web` commands.

```bash
anymous attach [url]
```

This allows using the TUI with a remote anymous backend. For example:

```bash
# Start the backend server for web/mobile access
anymous web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
anymous attach http://10.20.30.40:4096
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--dir"}</code></nobr>      |       | Working directory to start TUI in                                          |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | Continue the last session                                                  |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | Session ID to continue                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | Fork the session when continuing (use with `--continue` or `--session`)    |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | Basic auth password (defaults to `ANYMOUS_SERVER_PASSWORD`)               |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | Basic auth username (defaults to `ANYMOUS_SERVER_USERNAME` or `anymous`) |

### auth

Command to manage credentials and login for providers.

```bash
anymous auth [command]
```

---

#### login

anymous is powered by the provider list at [Models.dev](https://models.dev), so you can use `anymous auth login` to configure API keys for any provider you'd like to use. This is stored in `~/.local/share/anymous/auth.json`.

```bash
anymous auth login
```

When anymous starts up it loads the providers from the credentials file. And if there are any keys defined in your environments or a `.env` file in your project.

##### Flags

| Flag                                     | Short | Description                                          |
| ---------------------------------------- | ----- | ---------------------------------------------------- |
| <nobr><code>{"--provider"}</code></nobr> | `-p`  | Provider ID or name to log in to                     |
| <nobr><code>{"--method"}</code></nobr>   | `-m`  | Login method label to use, skipping method selection |

---

#### list

Lists all the authenticated providers as stored in the credentials file.

```bash
anymous auth list
```

Or the short version.

```bash
anymous auth ls
```

---

#### logout

Logs you out of a provider by clearing it from the credentials file.

```bash
anymous auth logout
```

### mcp

Manage Model Context Protocol servers.

```bash
anymous mcp [command]
```

---

#### add

Add an MCP server to your configuration.

```bash
anymous mcp add
```

This command will guide you through adding either a local or remote MCP server.

---

#### list

List all configured MCP servers and their connection status.

```bash
anymous mcp list
```

Or use the short version.

```bash
anymous mcp ls
```

---

#### auth

Authenticate with an OAuth-enabled MCP server.

```bash
anymous mcp auth [name]
```

If you don't provide a server name, you'll be prompted to select from available OAuth-capable servers.

You can also list OAuth-capable servers and their authentication status.

```bash
anymous mcp auth list
```

Or use the short version.

```bash
anymous mcp auth ls
```

---

#### logout

Remove OAuth credentials for an MCP server.

```bash
anymous mcp logout [name]
```

---

#### debug

Debug OAuth connection issues for an MCP server.

```bash
anymous mcp debug <name>
```

### models

List all available models from configured providers.

```bash
anymous models [provider]
```

This command displays all models available across your configured providers in the format `provider/model`.

This is useful for figuring out the exact model name to use in [your config](/docs/config/).

You can optionally pass a provider ID to filter models by that provider.

```bash
anymous models anthropic
```

#### Flags

| Flag                                    | Description                                                  |
| --------------------------------------- | ------------------------------------------------------------ |
| <nobr><code>{"--refresh"}</code></nobr> | Refresh the models cache from models.dev                     |
| <nobr><code>{"--verbose"}</code></nobr> | Use more verbose model output (includes metadata like costs) |

Use the `--refresh` flag to update the cached model list. This is useful when new models have been added to a provider and you want to see them in anymous.

```bash
anymous models --refresh
```

### run

Run anymous in non-interactive mode by passing a prompt directly.

```bash
anymous run [message..]
```

This is useful for scripting, automation, or when you want a quick answer without launching the full TUI. For example.

```bash "anymous run"
anymous run Explain the use of context in Go
```

You can also attach to a running `anymous serve` instance to avoid MCP server cold boot times on every run:

```bash
# Start a headless server in one terminal
anymous serve

# In another terminal, run commands that attach to it
anymous run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--command"}</code></nobr>  |       | The command to run, use message for args                                   |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | Continue the last session                                                  |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | Session ID to continue                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | Fork the session when continuing (use with `--continue` or `--session`)    |
| <nobr><code>{"--share"}</code></nobr>    |       | Share the session                                                          |
| <nobr><code>{"--model"}</code></nobr>    | `-m`  | Model to use in the form of provider/model                                 |
| <nobr><code>{"--agent"}</code></nobr>    |       | Agent to use                                                               |
| <nobr><code>{"--file"}</code></nobr>     | `-f`  | File(s) to attach to message                                               |
| <nobr><code>{"--format"}</code></nobr>   |       | Format: default (formatted) or json (raw JSON events)                      |
| <nobr><code>{"--title"}</code></nobr>    |       | Title for the session (uses truncated prompt if no value provided)         |
| <nobr><code>{"--attach"}</code></nobr>   |       | Attach to a running anymous server (e.g., http://localhost:4096)          |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | Basic auth password (defaults to `ANYMOUS_SERVER_PASSWORD`)               |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | Basic auth username (defaults to `ANYMOUS_SERVER_USERNAME` or `anymous`) |
| <nobr><code>{"--dir"}</code></nobr>      |       | Directory to run in, or path on the remote server when attaching           |
| <nobr><code>{"--port"}</code></nobr>     |       | Port for the local server (defaults to random port)                        |
| <nobr><code>{"--variant"}</code></nobr>  |       | Model variant (provider-specific reasoning effort)                         |
| <nobr><code>{"--thinking"}</code></nobr> |       | Show thinking blocks                                                       |
| <nobr><code>{"--auto"}</code></nobr>     |       | Auto-approve permissions that are not explicitly denied                    |

| <nobr><code>{"--mdns-domain"}</code></nobr> | Custom mDNS domain name                    |

## Environment variables

anymous can be configured using environment variables.

| Variable                              | Type    | Description                                       |
| ------------------------------------- | ------- | ------------------------------------------------- |
| `ANYMOUS_AUTO_SHARE`                 | boolean | Automatically share sessions                      |
| `ANYMOUS_GIT_BASH_PATH`              | string  | Path to Git Bash executable on Windows            |
| `ANYMOUS_CONFIG`                     | string  | Path to config file                               |
| `ANYMOUS_TUI_CONFIG`                 | string  | Path to TUI config file                           |
| `ANYMOUS_CONFIG_DIR`                 | string  | Path to config directory                          |
| `ANYMOUS_CONFIG_CONTENT`             | string  | Inline json config content                        |
| `ANYMOUS_DISABLE_AUTOUPDATE`         | boolean | Disable automatic update checks                   |
| `ANYMOUS_DISABLE_PRUNE`              | boolean | Disable pruning of old data                       |
| `ANYMOUS_DISABLE_TERMINAL_TITLE`     | boolean | Disable automatic terminal title updates          |
| `ANYMOUS_PERMISSION`                 | string  | Inlined json permissions config                   |
| `ANYMOUS_DISABLE_DEFAULT_PLUGINS`    | boolean | Disable default plugins                           |
| `ANYMOUS_DISABLE_LSP_DOWNLOAD`       | boolean | Disable automatic LSP server downloads            |
| `ANYMOUS_ENABLE_EXPERIMENTAL_MODELS` | boolean | Enable experimental models                        |
| `ANYMOUS_DISABLE_AUTOCOMPACT`        | boolean | Disable automatic context compaction              |
| `ANYMOUS_DISABLE_CLAUDE_CODE`        | boolean | Disable reading from `.claude` (prompt + skills)  |
| `ANYMOUS_DISABLE_CLAUDE_CODE_PROMPT` | boolean | Disable reading `~/.claude/CLAUDE.md`             |
| `ANYMOUS_DISABLE_CLAUDE_CODE_SKILLS` | boolean | Disable loading `.claude/skills`                  |
| `ANYMOUS_DISABLE_MODELS_FETCH`       | boolean | Disable fetching models from remote sources       |
| `ANYMOUS_DISABLE_MOUSE`              | boolean | Disable mouse capture in the TUI                  |
| `ANYMOUS_FAKE_VCS`                   | string  | Fake VCS provider for testing purposes            |
| `ANYMOUS_CLIENT`                     | string  | Client identifier (defaults to `cli`)             |
| `ANYMOUS_ENABLE_EXA`                 | boolean | Enable Exa web search tools                       |
| `ANYMOUS_SERVER_PASSWORD`            | string  | Enable basic auth for `serve`/`web`               |
| `ANYMOUS_SERVER_USERNAME`            | string  | Override basic auth username (default `anymous`) |
| `ANYMOUS_MODELS_URL`                 | string  | Custom URL for fetching models configuration      |
